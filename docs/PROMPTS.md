# Промты для Claude Code — по этапам

Как пользоваться:
1. Создай пустой репозиторий на GitHub и положи в корень `GAME_DESIGN.md`.
2. Открой репозиторий в Claude Code (веб-версия).
3. Отправь **Промт 0**. Дальше по одному промту на сессию. Новый этап начинай только когда предыдущий работает у тебя на ПК (скачал, запустил, проверил).
4. Если что-то сломалось, не начинай новый этап. Сначала используй промт «Исправление».

---

## Промт 0 — старт проекта

```
Ты ведущий разработчик большой 3D-игры «Кубач» на Godot 4. Полное ТЗ лежит в GAME_DESIGN.md в корне репозитория — прочитай его целиком, это главный источник правды.

Сейчас:
1. Создай CLAUDE.md с краткими правилами проекта (раздел 0 ТЗ), структурой папок (раздел 23) и командами сборки и тестов.
2. Скачай headless Godot 4 (последний стабильный, Linux x86_64) с GitHub Releases в tools/godot/, добавь его в .gitignore. Сделай скрипты scripts/check.sh (проверка скриптов), scripts/test.sh (GUT-тесты), scripts/export_windows.sh (экспорт .exe с export_presets.cfg).
3. Создай структуру проекта, project.godot (Forward+), подключи GUT, настрой Git LFS для ассетов.
4. Сделай Registry, который загружает data/*.json, и положи туда первые 10 блоков для проверки.
5. Опиши в CLAUDE.md, как ты будешь проверять производительность без видеокарты (счётчики, бенчмарк-сцена с логом frametime в файл).

Ничего не упрощай молча. Если что-то невозможно в этой среде — скажи прямо и предложи замену. В конце покажи, что сделано, и обнови раздел «Статус» в GAME_DESIGN.md.
```

## Промт этапа (шаблон для этапов 1–17)

Подставь номер и название этапа из раздела 24.

```
Выполняем ЭТАП [N]: [название] из GAME_DESIGN.md (раздел 24).

Перед кодом:
- перечитай разделы ТЗ, относящиеся к этому этапу;
- напиши в чат короткий план: какие файлы и системы, какие данные в data/, какие тесты.

Требования:
- всё контентное — в data/*.json, без хардкода;
- горячие циклы — в WorkerThreadPool, ничего тяжёлого в главном потоке;
- тесты GUT на ключевую логику, scripts/check.sh и scripts/test.sh должны проходить;
- не ломай предыдущие этапы, прогони все тесты;
- соблюдай цели производительности из раздела 20 (GTX 1660 / RTX 2060 Super);
- никаких синтезированных звуков и музыки, только хуки AudioManager и записи в assets/audio/MANIFEST.md.

В конце:
- обнови CHANGELOG.md и «Статус» в GAME_DESIGN.md;
- закоммить;
- дай мне чек-лист «что проверить руками на ПК» (5–15 пунктов) и список известных ограничений.
```

## Готовые уточнения для самых сложных этапов
Добавляй к шаблону, когда дойдёшь до этих этапов.

**Этап 1 (ядро мира):**
```
Особое внимание: детерминированность генерации (одинаковый сид = одинаковый мир, сделай тест), greedy meshing с отсечением граней, floating origin (проверь телепорт на 14 900, 14 900 — без дрожания), один прыжок высотой 1.25 блока, плавный переход камеры 1-е/3-е лицо по F5, сохранение только изменённых чанков в region-файлы.
```

**Этап 3 (графика):**
```
Блоки — кубы, но материалы PBR 128×128 (albedo, normal, roughness, AO) в Texture2DArray с 2–4 вариантами на блок. Если в assets/textures/source/ есть CC0-текстуры — сделай пайплайн (кроп, даунскейл, генерация нормалей, упаковка). Если нет — напиши tools/texgen/ на Python, который генерирует ДЕТАЛИЗИРОВАННЫЕ текстуры (трещины, слои, вкрапления, кора, годичные кольца), и покажи мне превью-лист всех текстур одним PNG. Настрой каскадные тени, SSAO, объёмный туман, glow, AgX, автоэкспозицию, траву MultiMesh с ветром, LOD чанков и пресеты Низкие–Ультра.
```

**Этап 6 (ремесло):**
```
Ремесло НЕ сетка 3×3. Реализуй раздел 5 полностью: сборка инструментов из частей со свойствами материалов, цепочки процессов во времени на станциях, сплавы по пропорциям, 5 уровней качества, мини-игры ковки, плавки и готовки (с опцией авто-режима), книгу рецептов с открытием рецептов.
```

**Этап 8 (вода):**
```
Клеточный автомат с 8 уровнями на блок, конечная вода в ведре, бесконечные природные источники, симуляция только в активных чанках со «сном», течение, сносящее игрока и предметы. Шейдер: волны, рефракция, SSR, каустика, глубинное затухание, пена, подводный туман и low-pass для звука. Тест: вылить 1 ведро в яму 3×3 — уровень должен выровняться, а объём сохраниться.
```

**Этап 14 (электричество):**
```
НЕ как редстоун. Сеть — граф, расчёт в отдельном потоке 4–10 раз в секунду. Вольты, ватты, ватт-часы, потери в проводах по длине и сечению, перегрузка → автомат выбивает или провод греется и искрит. Солнечные панели зависят от угла солнца, облачности, сезона и снега на панели. Аккумуляторы с КПД. Отопление с определением помещений и теплопотерями. Контроллер «ЕСЛИ датчик → ТО действие» с понятным UI. Планшет инженера с графиком выработки и потребления за сутки.
```

## Промт «Исправление»

```
Сборка работает не так, как надо. Вот что я вижу на своём ПК:
[описание + скриншот + текст ошибки из консоли Godot]
Найди причину, исправь, добавь тест, который ловит эту ошибку, прогони все тесты. Не трогай не связанные системы.
```

## Промт «Проверка производительности»

```
У меня [GTX 1660 / RTX 2060 Super], пресет [..], дальность [..] чанков, FPS [..], просадки при [..]. Вот лог бенчмарка: [вставь]. Найди узкие места (генерация, мешинг, отрисовка, ИИ, вода, частицы) и оптимизируй до целей раздела 20. Если GDScript не тянет — перенеси горячий цикл в C++ GDExtension.
```
